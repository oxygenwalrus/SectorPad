# Controller settings and profiles

SectorPad adds native LunaLib Mod Settings fields and a LunaLib Controller Setup panel. No Luna or vanilla settings widget is replaced. The current native menu contains 182 fields, including 108 distinct action mappings across UI, Campaign, Combat, Map, Tactical, and Deployment. Xbox and Steam Deck style controls use the same normalized physical button names. Guide is never a binding.

## Using the menus

Open Controller Setup from the command hub, or use the native Luna-configurable keyboard shortcut (F10 by default). D-pad or left stick selects a row; A chooses it. LB/RB chooses a game context. View cycles Bindings, Profiles, Tools, and Wheels. Menu closes the added panel. With a keyboard, up/down select a row, left/right choose a context, Enter chooses or confirms, Y previews, X/Delete unassigns, P changes section, and Escape cancels or closes. The native shortcut can be cleared to disable it. Mouse wheel scrolls the setup rows and left-click chooses a visible control.

Native Luna keyboard shortcuts default to F8 for the command hub, F9 for the on-screen keyboard, and F10 for Controller Setup. Each can be remapped or cleared independently. The hub gives keyboard access to the added menus without a connected controller.

On the Bindings page, A starts capture. Release every control and center both sticks for 200 ms, then press one button/trigger or move one stick and release it. Captures expire after 15 seconds. A control already used in the same context offers an explicit swap; A confirms that draft swap and B cancels it. Reuse in another context is legal. Buttons and vector controls have separate allowed types. Essential navigation and recovery access cannot be unassigned.

Y previews a draft for 15 seconds. A or Enter keeps the preview; B or Escape restores the previous saved profile while Controller Setup is open. Preview and confirmation are distinct actions, so pressing Y again does not save. Closing the panel, losing focus or the controller, changing the input owner, or allowing the preview to expire restores the committed profile. The runtime release/rearm callback fires whenever an effective mapping changes. Profile writes happen only after explicit confirmation; a write error keeps the previously committed mapping.

The Profiles page lists saved names and IDs. Selection starts a preview. Tools provides controller-operated duplication, calibration save, standard-control recovery, export, deletion, and import. Deletion has a second confirmation and cannot delete the active or built-in profiles. Export writes the committed profile as portable JSON to `SectorPad/exports/<id>.json` in game common data. Place imports under `SectorPad/imports/<id>.json` and list the filenames in `SectorPad/imports/index.json`, for example `{"files":["my-profile.json"]}`. The game API has no directory-listing operation, so this explicit index supplies the controller-selectable import list. Imports are validated before preview and do not immediately overwrite a saved mapping.

Native Luna Radio rows are a mapping proposal. Saving changed rows starts a preview. Both involved rows must be changed before saving a manual swap. Invalid proposals are rejected together. The native rows retain their proposal after a rejected/expired preview because LunaLib exposes no public settings setter. The committed profile and the Controller Setup panel remain the authority for active mappings. A persisted fingerprint prevents the same rejected proposal from being applied again on restart. Edit those native rows again or use Controller Setup to create another proposal.

## Tuning and calibration

Native Luna fields cover device selection, Xbox/Steam Deck labels, pointer speed/curve/deadzones, precision speed, independent scroll speed/curve/direction, map pan and zoom speed, navigation repeat, command wheel size and behavior, steering mode, aim distance, shield hold/toggle, latched drag, overlay scale, reduced motion, disconnect pause, and diagnostics.

Calibration has independent center offsets, radial deadzones, outer thresholds, response curves, and axis inversion for both sticks; both triggers have separate rest and maximum values. The Controller Setup diagram shows raw stick and trigger values. Set and save the Luna calibration values, then choose **Save Luna calibration for this controller** from Tools to persist them for the active device. Uncalibrated devices use the bounded native defaults. Calibration identities are SHA-256 hashes of the identity supplied by the controller backend; identical backend identities necessarily share calibration. Raw device identity strings are not stored.

The **Gyro and touch** Luna section controls optional Steam Input mouse-style gyro aiming. Mode selects combat aim, pointer use, both, or off. Combat aim captures mouse motion while its activation is held; Aim + pointer integrates the same deltas without consuming their normal cursor path. Activation gates combat gyro through a held controller control; sensitivity, smoothing and axis inversion are independent of stick calibration. Pointer-only mode requires no SectorPad cursor setting because Steam Input supplies ordinary mouse motion. Touch gestures have fixed conservative tap, drag and long-press thresholds so the same behavior applies before controller discovery.

The recovery chord is fixed outside the editable map: View + Menu held for two seconds. The runtime opens Controller Setup; Tools → Restore standard controls provides the normal 15-second confirmation path. The chord does not use Guide.

## Wheel order and section resets

Open a game wheel once so Controller Setup can discover its current commands, then select **Wheels** in Controller Setup. Choose a wheel with A/Enter, select a command, and press A/Enter to lift it. Up/down moves that command; A/Enter places it. Y saves the complete order, X stages the catalog's default order, and B/Escape discards unsaved edits and goes back. Closing setup also discards an unsaved order. Orders are separate for each saved profile and logical context. Missing commands keep their saved positions when they return; newly available commands append in their catalog order. Unavailable commands remain listed in the editor. Wheel ordering changes neither availability nor confirmation requirements for an action.

Tools offers resets for each of the six binding contexts, each controller's left stick, right stick, trigger calibration or complete calibration, and the current profile's wheel order. A binding reset preserves the profile name and other contexts, and uses the normal 15-second confirmation preview. Calibration and wheel reset tools require a second explicit confirmation. A profile JSON export/duplicate contains action bindings; wheel orders are stored separately under the profile ID.

Comfort resets cover device/shortcuts, pointer, scrolling, map movement, navigation repeat, wheel behavior, combat steering/aim, trigger button thresholds, and overlay appearance. Confirming a comfort reset activates SectorPad factory defaults for that section and persists the reset independently of Luna. Tools labels the section **defaults active** and offers **Use Luna values**. Changing and saving any native value in that section also clears its reset, while an edit in another section leaves it active. Native Luna widgets retain their saved values because LunaLib exposes no public setter; the reset help text and setup labels make this difference visible. These comfort resets apply across profiles, matching the native comfort settings. Per-device calibration resets affect only the connected device.

## Persistence and schemas

Action profiles and device calibration contain only primitive values, IDs, and control maps. They do not contain campaign/save objects. Runtime storage uses the supported `SettingsAPI` common-data operations under the `SectorPad/` namespace. The game chooses the physical common-data directory; the mod does not open an arbitrary operating-system path. Common data is separate from serialized campaign objects and survives replacement of the mod folder. An isolated game launch established that direct script file access is prohibited, so the runtime does not instantiate the separate `NioStorage` tooling backend.

The logical `profiles.json` document contains the active profile ID, the full named-profile collection, and the observed native proposal fingerprint. Each profile has action schema version 1, and the collection has its own schema version 1. `calibration.json` has a separately versioned device collection and independently versioned calibration entries. Native comfort preferences remain in LunaLib's own common-data file and are loaded into `ControllerSettings` snapshot schema 1.

`wheel-layout.json` schema 1 stores profile IDs, stable wheel IDs, and ordered stable command IDs only. Wheel titles, availability, game objects, and executable callbacks are never persisted. Each profile has at most 64 wheels and each wheel at most 256 commands. `preference-resets.json` schema 1 stores named comfort sections and the SHA-256 fingerprint of their native values at reset time. Both documents use the same checked common-data journal and last-good backup as profiles. Future schema versions block writes to their document.

Runtime `CommonStorage` writes a checksummed snapshot to an inactive slot, verifies its bytes, preserves the prior commit marker, then writes and verifies the new marker. Reads follow a valid committed marker and verify the payload checksum/generation; they never choose an uncommitted slot just because it is newer. If the current marker or payload is incomplete, the prior checked commit can be recovered. The profile layer separately retains a validated last known-good `.bak`. Damaged originals are preserved before an explicit replacement, and unknown future profile or journal versions block writes. A process-local nonblocking lock serializes SectorPad saves without waiting; the public game API exposes no cross-process lock. Documents are capped at the API's 1 MiB limit, collections at 64 profiles/devices, and profile IDs at 48 safe filename characters. This first schema does not guess at a predecessor format or silently migrate unknown versions.

`SettingsAPI.readTextFileFromCommon(String)`, `writeTextFileToCommon(String,String)`, and `fileExistsInCommon(String)` are the runtime I/O boundary. The API exposes neither atomic rename nor fsync, so `usedAtomicReplacement()` correctly returns false. Fault-injection tests establish process-level recovery for the modeled incomplete writes; they do not establish power-loss durability. The explicit headless `NioStorage(Path)` backend retains temporary-file writes, flushes, atomic replacement where supported, and a nonblocking filesystem lock for offline tools and tests. It is not the runtime fallback.

## Integration API

```java
SettingsService service = new SettingsService(ProfileStore.inCommonData());
service.setListener(new SettingsService.Listener() {
    public void changed(ControllerSettings settings, BindingProfile profile) {
        // Release all SectorPad-owned input and require neutral input before rearming.
    }
    public void statusChanged(String status) {
        // Present local status to the player.
    }
});
service.initialize();
service.refresh(); // Also after campaign/new-game load; Luna skips its new-game listener.
service.advance(System.nanoTime());
```

Runtime reads `service.settings()`, `service.activeProfile()`, and `service.calibration()`. Supply the current controller identity with `setDevice(String)`. `BindingProfile.binding(context, action)` returns the normalized input ID; `bindings(context)` and `contexts()` are immutable. `withBinding` rejects conflicts and `withSwap` makes a validated, context-local exchange.

At wheel construction call `service.orderWheel(stableWheelId, label, entries, idFunction, labelFunction)`. It returns an immutable reordered list and registers ID/label metadata for the setup editor. The runtime uses IDs such as `UI:hub`, `CAMPAIGN:abilities`, and `COMBAT:weapons`; screen instances and localized titles must not be identifiers. `wheelCatalogs()` and `wheelEntries(id)` expose immutable editor metadata. `saveWheelOrder(id, ids)`, `resetWheelOrder(id)`, and `resetAllWheelOrders()` persist explicit user edits. No write occurs just from opening a wheel. Settings changes and order saves invoke the existing release/rearm callback.

`previewResetBindings(context)` previews a context-local reset; `resetCalibration(DeviceCalibration.Section)` resets only a connected device's chosen section. `resetPreferenceSection(PreferenceResets.Section)` and `useLunaPreferenceSection(section)` manage comfort defaults; `activePreferenceResets()` supplies the visible reset indicators.

`LunaRemappingPanel(SettingsService, Supplier<InputState>, Runnable closeOwnPanel)` mounts through `initFromScript(CustomPanelAPI)`. Runtime input uses `LunaRemappingPanel.InputState.fromFrames(calibrated, raw, focused)`, whose signature is `fromFrames(PadFrame normalized, PadFrame raw, boolean focused)`. Supply the same calibrated frame used by gameplay and menus. The `buttons` and axis fields control navigation, neutral gating, and remap capture; calibrated trigger thresholds and hysteresis remain authoritative. The separate `rawButtons`, `rawLeftX/Y`, `rawRightX/Y`, and `rawLeftTrigger`/`rawRightTrigger` fields retain device samples for the diagram and calibration readouts. A nonzero raw trigger rest value therefore cannot prevent capture from arming when its calibrated value is neutral.

The compatibility constructor still accepts `(Set<String> buttons, float leftX, float leftY, float rightX, float rightY, float leftTrigger, float rightTrigger, boolean connected, boolean focused, String deviceName)`. Its axes serve as both normalized values and raw readouts, and it retains legacy trigger synthesis. Use the paired-frame factory for runtime integration. While mounted, give the panel exclusive controller ownership. Call `panel.onClose()` or `panel.closePanel()` on lifecycle removal so it reverts unconfirmed input and invokes the owner callback. For a script-mounted panel, do not call Luna's global Escape handler or its final `close()` method; those affect shared Luna selection state. For a campaign-dialog-owned panel, `close()` handles the public dialog dismissal.

## Verification

Compiled with Java `--release 17` against installed Starsector API/JSON/LWJGL and LunaLib 2.0.5 jars. `sectorpad.settings.SettingsTests <absolute path to LunaSettings.csv>` passes 2,956 headless assertions. Coverage includes native/runtime catalog agreement, canonical action-row ordering after unordered imports, tuning bounds, full-context validation, conflict swaps, capture neutral/release gating, independent trigger capture, finite radial output, named-profile persistence, corrupted-primary backup recovery, future-schema preservation, imports/exports, device identity hashing, busy writers, delayed confirmation rejection, preview rollback, controller discovery tests, restart behavior, device changes, and failed writes. Common-API fault injection additionally covers partial inactive slots, partial commit markers, payload checksum damage, uncertain write completion, uncommitted first snapshots, future journal versions, and plain portable exports. Wheel/reset tests also cover stable IDs across missing/new commands, profile and context isolation, explicit order saves, profile-deletion cleanup, reset rollback, independent device sections, comfort-section ownership, restart persistence, native-edit reconciliation, and future-schema write protection.

The paired-frame input boundary was separately compiled and tested with `sectorpad.settings.SetupInputTests`: 29 headless checks pass. They cover calibrated trigger rest offsets and reduced ranges, threshold/hysteresis ownership, normalized navigation and vector capture, independent raw diagnostics, invalid normalized samples, immutable snapshots, and compatibility with the existing constructor. These tests initialize neither a Luna panel nor a controller; the full builder discovers the test class automatically.

An isolated Windows session at **1280 × 800**, operated with keyboard and mouse and no physical controller, loaded all **182 native Luna rows**. Controller Setup worked from the title screen, a saved campaign, native cargo, and refit. Southpaw preview and commit passed, and the saved profile [persisted after a full game process restart](evidence/profile-persisted-after-restart.png). An unconfirmed preview [expired after 15 seconds and restored saved Southpaw](evidence/profile-preview-expired.png); Standard was subsequently committed successfully.

The same session verified wheel ordering in `UI:hub`: Keyboard was lifted from position 2, moved to position 1, placed, and [saved with Y](evidence/wheel-order-saved.png). X then staged the default order and [Escape discarded that unsaved reset](evidence/wheel-reset-discarded.png). Reopening retained Keyboard first, and the [live hub reflected the saved order](evidence/wheel-order-applied.png). A later full process restart at 1280 × 720 also retained that order. At that resolution, the [native Luna menu](evidence/luna-settings-1280x720.png) remained unobscured, and Controller Setup supported page navigation and closure over the simulation deployment picker.

Physical controller operation, calibration usability on actual devices, and Linux/SteamOS remain unverified. These Windows settings results establish the stated keyboard/mouse journeys at 1280 × 800; they do not establish hardware focus/disconnect recovery. A separate [campaign removal test](COMPATIBILITY.md) saved with SectorPad active and successfully reloaded after its complete mod directory was removed.
